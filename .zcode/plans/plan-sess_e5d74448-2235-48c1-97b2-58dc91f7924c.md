# 提示词增强迁移到统一执行链路(对齐生成提交消息模式)

## 背景与决策

现状:增强是 desktop main 进程旁路(UI → preload IPC → main 直读 `~/.zcode/v2` 配置 + 解密凭据 + 渠道评分 + 裸 fetch),Web 不可用。目标:完全对齐提交消息模式 —— UI → 服务 RPC → services 层协作者 → `generateWorkspaceText`(querySource 特判)→ 统一执行面。

已确认决策:**跟随会话模型**(删渠道选择菜单/评分/localStorage);**彻底删除旧旁路**(main 三个文件 + IPC + preload + platform 可选方法)。迁移后 Web 端按钮变为可用(行为改进)。

## 风险与边界

- 旧能力(手动渠道 enhance-config.json、渠道评分、oauth 跨渠道兜底)随旁路删除而消失(已确认)。
- preferredSelection 为空(未选模型)→ 失败 toast,与提交消息行为一致。
- sanitize 清空回退原文逻辑必须保留(防止模型坏响应清空草稿)。
- remoteWorkspaceServiceCollection(desktop-attached-remote)按需补注册,保持远程链路可用。
