## Context

用户实测反馈四件事（前一轮拖拽功能的后续）：
1. **一次只能拽一个文件**，要求支持一次拽多个；
2. 拖入文件显示成**附件卡片**，希望显示为 `@README.md` `@droptest.txt` 这样的 mention pill；代码选区上下文要显示 `@droptest.txt 500-666` 带行号的形式；
3. 资源管理器右键「加入 Gode 对话」点击无反应；
4. 编辑器选中代码 → Gode →「加入对话上下文」（⌘⌥A）无反应。

调查结论（代码链路确认 + 现场复现）：
- **③④ 根因（已复现）**：`packages/ui/src/v4/SessionPane.tsx:4377` 的 gate `focused && sessionId === null` —— 有活动会话时 composer-insert 请求被**静默丢弃**（悬空在 store，无人清理）。复现：右键文件点击后面板切到新建任务草稿，composer 无 pill。次级断点：同文件第二次加入按 `category+value` 判重返回假成功（同文件不同行选区也被误判重复，`LexicalChatInput.tsx:275-315`）；面板从未打开时 `pushHostFrame` 投空 + `chatPanel.reveal()` 空操作（webview 懒解析，`hostRuntime.ts:83-88`）；多文件时 host 循环 push N 帧（`editorCommands.ts:93-102`）落在 store 单槽上有竞态。
- **①② 语义变更**：现有附件管线对多文件本身支持（uri-list 多行），但产物是附件卡片；用户要的是 mention pill（与仓库既有「文件树拖拽 = mention」语义一致）。`appendFileMention`（`LexicalChatInput.tsx:385-422`）是纯追加、无去重、可循环 N 次 —— 多文件 mention 的现成载体；选区行号 label 可复用 `contextCollector.ts` 的 start/end（现 label 已是 `path:9-20` 形式）。
- **边界**：从编辑器**拖拽**选中文本到聊天区，DOM dataTransfer 只有 text/plain（无来源文件/行号），纯 drop 侧无法实现 `@file 500-666`；该形式由修复后的 ⌘⌥A 命令承担。

## 修改方案

### A. composer-insert 投递链修复（修③④）
1. **gate 放宽** — `SessionPane.tsx:4377`：`focused && sessionId === null` → `focused`（活动会话时 mention 落进排队输入框）。
2. **批量 mention** — `store/zcodeSessionStoreTypes.ts` `ComposerTextInsertRequest` 加 `mentions?: ComposerMentionPrefill[]`（保留单数 `mention` 兼容）；`zcodeSessionStoreWorkspaceSlice.ts` `requestComposerTextInsert` 接受批量；`ConversationComposer.tsx` `applyExternalTextInsertRequestToComposer` 循环应用（prepend 语义按逆序保持原顺序，或新增顺序追加 helper），文本侧一次 updateText。
3. **host 改单帧批量** — `features/editorCommands.ts` `addContext`：N 条 mention 合并为**一个** composer-insert 帧（text = 各 markdown 连接，mentions 数组）。
4. **判重改按 id** — `LexicalChatInput.tsx` `prependEditorMentionIfMissing` 按 `mention.id` 去重（host 侧 id 已含行号后缀，同文件不同选区不再误判）；被去重时至少 requestFocus 给反馈。
5. **帧排队** — `host/hostRuntime.ts`：无 webview 连接时 pushHostFrame 进入有界队列（≤32，FIFO），在收到 webview 首条消息（bootstrap ctx/notifyRendererReady）时按序 flush —— 修「面板从未打开」场景。
6. **诊断** — `editorCommands.ts` 链路加 debug 日志（帧数/mention 数）。

### B. 拖拽语义改为 mention pill（修①②）
7. **drop 分支迁移** — `ConversationComposer.tsx` `handleConversationDrop`：workspace MIME 分支后新增 explorer 分支——`hasExplorerResourceDragSignal(types)` 且 `parseFileUriList` 有结果且 `platform.resolveFileDropPaths` 存在 → preventDefault → resolve 后**循环 `appendWorkspaceFileMentionToComposer`**（每个文件一个 pill，天然支持多文件；同 workspace 用 relativePath，跨目录用绝对路径——现有 helper 已处理）。
8. **回退附件分支** — `useComposerAttachments.ts` 删除上一轮加的 uri-list→附件分支（drop 判序：workspace MIME → explorer mention → `Files` 附件兜底）；**保留** dragover 识别（视觉反馈不变）与 `resolveFileDropPaths` 平台方法。
9. **选区 pill 行号显示** — `features/contextCollector.ts`：label 改为 `${basename} ${start}-${end}`（用户格式），mention id 保持含行号；`packages/ui/src/mentions/nodes/PromptMentionNode.ts` 检查 displayLabel：files 类若强制 basename 则扩展为「data 带行号时显示 `basename start-end`」，同步 `updateDOM` 比较白名单。

### C. Spec
- 更新 `docs/spec/composer-explorer-file-drop.md`：语义从附件改为 mention pill（多文件）、图片等仍可后续讨论；
- 新建 `docs/spec/composer-insert-delivery.md`：gate、批量、帧排队、判重 id 化的规则与验收场景。
