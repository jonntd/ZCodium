# VS Code 扩展「文件改动审查与历史」实现计划

## Context

当前 AI（CLI 运行时）改完文件后，用户只能在聊天流的逐轮文件卡片里看到改动并撤销，编辑器侧完全无感。目标是对齐 Augment/TRAE 式 Changes 体验：

1. AI 每轮改动文件后，VS Code 中**可按需打开**该文件的原生双栏 Diff（左=改动前，右=当前磁盘文件）；
2. 每个文件可**独立撤销**（恢复到本轮改动前，逐字节一致）或**保留**；
3. 跨轮次的**修改历史**可在侧边栏 TreeView 浏览并随时恢复。

**用户已拍板**：呈现形态=原生双栏 Diff；**不自动打开**文件（轮完成后仅在 TreeView/状态栏提示，用户点击才开 Diff）；历史入口=侧边栏 TreeView。

**CLI 零改造**（探查已确认全部现成）：
- 检查点：每文件改动生成 artifact（改动前全文+structuredPatch），`tool-result-settlement.ts:184-199` → `helpers/rewind.ts:58-81`；
- 逐文件撤销：v4 命令 `applyFileRewind { target, paths? }`（`packages/shared/src/zcode-protocol-v4/command.ts:172-175`），**CAS 命令必须带 baseRevision**（`command.ts:326-342`）；
- 撤销预检：`conversationFileRewindPreviewV4`（`packages/services/src/zcode-agent/zcodeAgent.ts:978-980`），含 external_modified 哈希检测；
- 轮改动明细：`conversationFileChangesV4`（zcodeAgent.ts:974-976）返回每文件 `{path, additions, deletions, patches}`；
- 轮完成信号：conversation 帧流 `onDynamicConversationFrame`（zcodeAgent.ts:1001-1003）中 turnHeader 行 `state: completedSuccess|completedInterrupted|failed` + `fileChanges{files>0, state:"active"}`（rows.ts:101-111）；
- 宿主派发命令：`sendConversationCommandV4({workspacePath, workspaceIdentity?, envelope})`（zcodeAgent.ts:980，webview transport 底层同款）。

## 架构与事件顺序

```
CLI 运行时                     扩展宿主 (apps/zcode-vscode)                VS Code 编辑器
──────────                    ───────────────────────────                ─────────────
tool 写文件 → checkpoint
轮结束 TurnComplete
  │ row.upserted(turnHeader,
  │   state=completedSuccess,
  │   fileChanges{files>0})
  ▼
onDynamicConversationFrame ──▶ ChangesTracker（纯状态机,零 vscode）
(crate 帧订阅;                  ① 识别轮终态+改动数>0
RuntimeController              ② conversationFileChangesV4 拉明细
 onAgentRuntimeRestarted       ③ 更新 pending/history 状态
 时经此重订)                    ④ 发 onChange 事件
                                  │                    │
                                  ▼                    ▼
                          HistoryTree(TreeView)   StatusBar(待审计数)
                          待审查/历史 两段            ⚠ n
                                  │
                          用户点击文件 ──▶ DiffOpener: vscode.diff(改动前虚拟文档, 磁盘文件)
                          标题栏[撤销][保留] ◀── setContext("gode.pendingFile")
                                  │
              撤销: conversationFileRewindPreviewV4 预检
                → canApply? sendConversationCommandV4(applyFileRewind,
                   envelope{commandId,clientId,sessionId,baseRevision,paths})
                → ack.applied → CLI 落盘恢复 → RewindTriggered 事件
                → 帧流 row.upserted(fileChanges.state=reverted/revertedPaths)
                → Tracker 更新 → Tree/状态栏刷新
                → 重新打开的 diff 显示「已恢复」
```

状态所有者：**ChangesTracker 是 pending/history 唯一所有者**；文件内容以磁盘为准（撤销落盘由 CLI 执行）；webview 不参与（聊天内既有 ConversationFileSummaryPanel 独立工作，两处通过 CLI 事件天然同步）。

## 实现步骤

### 0. 先写 spec（AGENTS.md 核心原则：先 spec 后代码）
新建 `docs/spec/vscode-pending-changes.md`：状态所有者（Tracker）、事件顺序（上图）、接口（Tracker 输入帧/输出事件、Tree 节点模型）、验收场景（下文验证节 9 条）。

### 1. 新建 `src/host/pendingChanges/`（headless 优先，便于 vitest 直测）
- **`types.ts`**：`PendingFileChange{path, sessionId, turnId(rowId), turnTitle, additions, deletions, patches, status}`、`HistoryTurnEntry`、`ChangesSnapshot`。
- **`beforeContent.ts`**（纯函数）：把 `DiffHunk[]`（`{oldStart,oldLines,newStart,newLines,lines[]}`，前缀空格/`-`/`+`）**反向应用**到当前磁盘内容，重构「改动前」全文供 diff 左栏。失败返回 null（降级为只读打开当前文件）。补齐：文件被 AI 删除时右栏用空虚拟文档。
- **`changesTracker.ts`**（纯状态机，零 vscode 依赖）：
  - 输入：conversation 帧（snapshot 全量重建 + row.upserted 增量）、`conversationFileChangesV4` 结果；
  - 规则：轮终态+files>0+state=active → pending 新增；同路径被新一轮改写 → pending 指向最新轮，旧轮沉入历史且标记「已被后续改动覆盖」（哈希预检也必然拦截，语义一致）；保留/撤销成功 → 移出 pending、历史标记；消费 `revertedPaths` 更新历史；
  - 顺带跟踪帧流中的 `baseRevision/baseLogEpoch`（供 CAS 信封）；
  - 输出：不可变快照 + onChange 事件。
- **`changesService.ts`**（vscode 面编排）：经注入的 services accessor 订阅帧流（挂在 container，随 `onAgentRuntimeRestarted` 经 RuntimeController 重订——zcodeAgent.ts:1056-1060 约束）；拉明细；构造 v4 信封（uuidv7 from @zcode/shared、宿主自持 clientId 存 globalState、`COMMANDS_REQUIRING_BASE_REVISION` 校验）派发 `applyFileRewind`；预检不通过（external_modified 等）弹中文警告且不动文件；pending/history 持久化到 workspaceState（上限 100 轮，重启恢复后以预检为准）。
- **`diffOpener.ts`**：复用 `diffViewer.ts` 的 `zcodium-proposed` scheme（小重构：ProposedContentProvider 支持注册任意 before 内容），`executeCommand("vscode.diff", beforeUri, fileUri, "文件名 (改动前 ↔ 当前)", {preview:true})`——范式同 `quickEdit.ts:119-125`（仓内唯一真正用 vscode.diff 的样板；现 DiffViewer.open 未调 vscode.diff 的缺陷顺带修正）。
- **`historyTree.ts`**：TreeDataProvider，两个分组——「待审查」（文件节点：basename、+N -M 描述、点击开 diff、行内按钮 撤销/保留；轮节点带 全部撤销/全部保留）与「历史」（按轮倒序：轮标题+时间 → 文件子节点；最新写入轮可点开 diff 与恢复，旧轮显示「已被后续改动覆盖」禁用恢复）。

### 2. 接线与贡献点

- **`src/ui/statusBar.ts`**：仿 `setPendingApprovals`（:55-58）加「📝 n 待审」计数，点击打开 TreeView 聚焦。

## 验证
1. `pnpm --filter zcode-vscode test`（vitest，含上述新测试）；
2. `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed`；
3. 手动验收（spec 9 条）：AI 改 2 文件→TreeView 待审 2 项+状态栏计数；点开 diff 左右正确；撤销后文件逐字节等于改动前（与 CLI artifact beforeContent 一致）；保留后从待审消失；撤销前手改文件→弹 external_modified 警告不落盘；新一轮改同文件→pending 指向最新轮；重启 VS Code→pending/历史恢复且撤销可用；AI 删除文件→撤销后文件消失；全部测试真实执行并报告结果。

## 明确不做（本计划范围外）
单栏幽灵删除行内联 diff（VS Code 公开 API 不可达）、轮完成后自动打开文件（用户已排除）、Redo（重应用已撤销内容）、webview 聊天卡片改动、CLI 协议/引擎改动。
